# Harness Done

Mark the current task as complete using the MCP tool.

## What Happens

When you complete a task with `harness_complete`, it automatically:
1. Marks the task status as "done"
2. Clears any saved checkpoint for the task
3. **Appends a timestamped entry to CHANGELOG.md** under `[Unreleased]`
4. Optionally creates a git commit (if `auto_commit=True`)

## Instructions

1. First, find the current "doing" task:
```
find_tasks(project_id="b903113d-2a15-4225-888d-c4ff2a8d4389", filter_by="status", filter_value="doing")
```

2. If no "doing" task found, inform user and stop.

3. Summarize what was accomplished for this task.

4. Ask user about git commit preference:
   - Auto-commit (recommended): MCP tool commits inside container (fast)
   - Manual commit: User commits later on home server
   - Skip to review: Move to "review" status instead of "done"

5. Call the MCP tool to complete the task:
```
harness_complete(task_id="<task_id>", auto_commit=True)
```
   - Set `auto_commit=True` for automatic git commit
   - Set `auto_commit=False` to skip git (user commits manually)

6. If user chose "review", use manage_task instead:
```
manage_task(action="update", task_id="<task_id>", status="review")
```

7. Show the result and offer to continue to next task.

## Commit Message Format (auto-generated by MCP tool)

The `harness_complete` tool generates commits in this format:
```
feat: <task_title>

Task-ID: <task_id>
```

For custom commit messages, pass `commit_message` parameter:
```
harness_complete(task_id="<id>", auto_commit=True, commit_message="custom message here")
```

## Usage

User: "/harness-done" or "mark task complete"

## Why Use MCP Tool?

Git commands run **inside the MCP container** where files are local.
This avoids slow SSHFS operations when Claude Code runs on a remote VPS.

## Post-Completion Options

After completing, ask user:
- Continue to next task? (`/harness-next`)
- Push to remote? (user runs `git push` on home server)

## Manual Commit Alternative

If auto_commit=False, provide commit command for home server:
```bash
cd ~/archon
git add <files>
git commit -m "feat(<scope>): <description>

Task-ID: <task_id>"
```

## Changelog Entry Format

The tool automatically appends entries to `CHANGELOG.md` under `## [Unreleased]`:

```markdown
### Added
- **2026-01-15 06:30** - Implement checkpoint system for task progress (Task: 1852208f)
```

**Entry placement:**
- Task titles starting with `feat(...)` → `### Added`
- Task titles starting with `fix(...)` → `### Fixed`
- Task titles starting with `refactor(...)` or `chore(...)` → `### Changed`
- Other titles → `### Added` (default)

**Entry format:**
```
- **YYYY-MM-DD HH:MM** - <task_title> (Task: <short_id>)
```

The changelog response is included in the tool output:
```json
{
  "changelog": {
    "success": true,
    "entry": "- **2026-01-15 06:30** - ...",
    "section": "Added",
    "file_path": "/path/to/CHANGELOG.md"
  }
}
```
